==== Was habe ich aus dem Tutorial gewonnen (aka gelernt)?

*Kannte ich schon gut:*

* *Big O Notation* — Laufzeit- und Speicherkomplexität mit wachsender Eingabegrösse n: O(1) konstant, O(log n) logarithmisch, O(n) linear, O(n log n), O(n²) quadratisch. Es geht um Wachstumsverhalten, nicht um exakte Millisekunden.
* *Stack (LIFO – Last In, First Out)* — Wie ein Tellerstapel: `push()` legt oben drauf, `pop()` nimmt oben weg, `peek()` schaut oben hin ohne zu entfernen. Anwendungsfälle: Undo-Funktion, Browser-Zurück, Rekursions-Aufrufstack.
* *Queue (FIFO – First In, First Out)* — Wie eine Warteschlange: `enqueue` hinten anstellen, `dequeue` vorne bedient werden. Anwendungsfälle: Druckerwarteschlange, Task-Scheduling.

*Kannte ich zum Teil — neues Wissen gewonnen:*

* *Priority Queue* — Wie eine Queue, aber Elemente haben eine Priorität; höchste Priorität wird zuerst bedient, unabhängig von der Eintreff-Reihenfolge. In Java: `PriorityQueue`-Klasse, nutzt intern einen Heap.
* *Linked List* — Kette von Nodes (Wert + Pointer auf nächsten Node), kein zusammenhängender Speicherblock nötig. Einfügen/Löschen an bekannter Stelle O(1), aber Index-Zugriff O(n). Varianten: Singly Linked List, Doubly Linked List.
* *Dynamic Arrays* — Array, das bei Bedarf automatisch wächst (Kapazität verdoppeln, wenn voll). Grundlage von Javas `ArrayList`. Amortized O(1) pro `add`, weil Verdoppelungskosten selten anfallen.
* *LinkedList vs. ArrayList* — `ArrayList`: schneller Index-Zugriff O(1), Einfügen/Löschen in der Mitte O(n). `LinkedList`: Einfügen/Löschen an bekannter Stelle O(1), kein Index-Zugriff O(n). Faustregel: viele Lesezugriffe → `ArrayList`; viele Einfügungen/Löschungen → `LinkedList`.

==== Spass gemacht hat?
Der Kurs visualisiert Pointer-Operationen anschaulich — das hat geholfen, Linked Lists nochmals klarer zu sehen. Schön, bekannte Themen mit mehr Tiefe zu betrachten und den Unterschied ArrayList vs. LinkedList endlich sauber erklärt zu sehen.

==== Mühsam war?
Da viel Grundwissen schon vorhanden war, war der Einstieg etwas langsam. Priority Queue und Heap-Interna waren kurz und wären mehr Tiefe wert gewesen.

==== Was ich noch Anschauen will
* Rest des Kurses (ab Minute 60): Trees, Hash Maps, Graphs, Sorting Algorithms.
* Heap-Datenstruktur im Detail — wie `PriorityQueue` intern funktioniert.

==== Welche/s Tutorial/s habe ich durchgearbeitet?
— Java Kurs Fortgeschritten (Generics, Functional Interfaces, Threads, File I/O)
1h 51 min

==== Was habe ich aus dem Tutorial gewonnen (aka gelernt)?

*Generics:*

* Generics ermöglichen es, Methoden und Klassen für verschiedene Typen wiederverwendbar zu machen — ohne für jeden Typ eine eigene Version schreiben zu müssen.
* Beispiel: eine generische `contains`-Methode (`boolean contains(T[] array, T value)`) deckt beliebige Typen mit einem einzigen Aufruf ab.
* Eigene generische Klassen schreiben, z.B. eine `Pair<A, B>`-Klasse, die zwei Werte unterschiedlicher Typen kapselt.
* Wildcards (`?` und `? extends T`) erlauben flexible Typparameter bei generischen Methoden und Klassen.
* *Type Erasure*: Zur Laufzeit werden die Typinformationen aus Generics entfernt — Java ersetzt sie durch `Object` oder die obere Schranke. Typprüfungen finden also nur zur Compile-Zeit statt, nicht zur Laufzeit.

*Optional mit Streams:*

* `Optional<T>` als Wrapper für potenziell fehlende Werte — vermeidet `NullPointerException` durch explizites Behandeln des Fehlerfalls.
* Kombination von `Optional` mit der Stream API (z.B. via `flatMap` oder `filter`) für elegantere Fehlerbehandlung innerhalb von Pipelines.

*Functional Interfaces & Stream API:*

* Functional Interfaces fokussieren auf das *Was* (deklarativ), nicht das *Wie* (imperativ) — man beschreibt das gewünschte Ergebnis, nicht den Rechenweg.
* `Consumer<T>`: nimmt einen Wert entgegen und gibt nichts zurück — nützlich für Seiteneffekte wie Ausgaben oder Logging.
* `Predicate<T>`: nimmt einen Wert und liefert einen `boolean` — ideal als Filterbedingung in Streams.
* Kombination von Functional Interfaces mit der Stream API ermöglicht kompakte, gut lesbare Datenpipelines.
* Rückblick auf Prog1-Aufgaben: viele hätten sich mit Functional Interfaces eleganter lösen lassen.
* `Runnable`-Interface kennengelernt: kapselt eine ausführbare Aktion ohne Parameter und ohne Rückgabewert — dient als Grundlage für Threads.

*Concurrent Programming:*

* `Thread`-Klasse kennengelernt: ermöglicht die parallele Ausführung von Code in separaten Ausführungssträngen.
* `synchronized` bei Methoden verhindert Race Conditions, indem sichergestellt wird, dass immer nur ein Thread gleichzeitig auf die Methode zugreifen kann.
* Leichte Einführung in die Grundkonzepte der nebenläufigen Programmierung — ein Thema, das deutlich mehr Tiefe hat als in dieser Einheit abgedeckt.

*File I/O:*

* `FileReader` und `BufferedReader` kombinieren: `FileReader` öffnet die Datei zeichenweise, `BufferedReader` puffert den Zugriff für effizienteres zeilenweises Lesen mit `readLine()`.

==== Spass gemacht hat?
Die Generics-Thematik war sehr aufschlussreich — besonders der Moment, als klar wurde, wie viel Redundanz eine einzige generische Methode eliminieren kann. Functional Interfaces haben einen neuen Blickwinkel auf das Lösen von Problemen eröffnet: deklarativ statt imperativ zu denken fühlt sich eleganter und ausdrucksstärker an. Der Rückbezug auf Prog1-Aufgaben hat das Gelernte greifbar und konkret gemacht.

==== Mühsam war?
Type Erasure war anfangs schwer zu greifen — das Konzept, dass Typinformationen zur Laufzeit verschwinden, ist nicht intuitiv. Concurrent Programming war dichtes Terrain: viele neue Konzepte auf einmal, die sich nicht sofort vollständig setzen.

==== Was ich noch Anschauen will
* Concurrent Programming vertieft anschauen — insbesondere Deadlocks, `ExecutorService` und `Future`
* Nested Classes (noch offen vom Vortag)

— Java Grundkurs 2 / 2h 25min

==== Was habe ich aus dem Tutorial gewonnen (aka gelernt)?

*Konventionen & Grundlagen:*

* Static-Variablen werden per Konvention komplett in Grossbuchstaben geschrieben.
* `equals` und `hashCode` müssen immer beide überschrieben werden — nur eine zu ändern führt zu inkonsistentem Verhalten.

*Objektorientierung:*

* Vererbung mit `extends`: eine Klasse erbt alle Methoden und Felder der Elternklasse und kann sie bei Bedarf überschreiben.
* Records kennengelernt — eine kompakte Möglichkeit, unveränderliche Datenklassen zu definieren, ohne Boilerplate wie Getter oder Konstruktor manuell schreiben zu müssen.

*Fehlerbehandlung:*

* `try-catch`-Blöcke für die Fehlerbehandlung; Fehlerausgaben über `System.err` statt `System.out`, damit sie klar als Fehler erkennbar sind.
* Checked Exceptions: Ausnahmen, die vom Compiler erzwungen werden und explizit behandelt oder weitergegeben werden müssen.
* Spezifische Exception-Typen im `catch`-Block ermöglichen gezielte Fehlermeldungen pro Fehlerfall.

*Streams:*

* Streams kennengelernt — ermöglichen funktionale Verarbeitung von Datenmengen, z.B. mit `filter`, `map` oder `collect`.
